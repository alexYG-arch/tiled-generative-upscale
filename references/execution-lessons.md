# 本次执行提供的经验

这份记录说明 Skill 的设计依据，**不构成新 Skill 已完成真实生图运行的证明**。脚本自测、Skill 结构校验与真实生成后的视觉验收应分别报告。

## 已知事实

源图为 1920×1080 的红金海报，目标是宽高各 10 倍，即 19200×10800。用户指出第一次处理看起来只是拼合后放大，随后执行改为 17 列×12 行，共 204 个带重叠裁切，每块输入 128×108，拼合目标每块 1280×1080。

执行目录保存了 204 张独立生成图和对应提示词。记录中的原生输出包括 1449×1086、1366×1152 等多种尺寸，最终直接拼合到目标画布。受保护的文字、标志和红色留白使用了原图派生处理；这些区域并不是全新生成的细节。

204 块只是这张图片、这次倍率与切片选择的结果，不是默认数量。切片数量必须根据新图、倍率、实际原生容量、重叠和内容调整重新计算。

## 应保留的做法

- 按每块的目标像素规模进行独立生成，保留原始生成图和实际提示词；最终画布直接使用目标尺寸。
- 使用整图上下文和统一材质描述，保留跨块对象的颜色、比例和细节尺度。
- 在长批次中保存进度，先检查代表性块及相邻块，再扩展运行。
- 同时检查缩小整图与 100% 局部；图像尺寸正确不能证明细节或接缝正确。
- 如实说明生成式重建与原图保护的边界，不声称生成纹理就是丢失的真实拍摄细节。

## 不应照搬的旧实现

| 旧实现的问题 | 新 Skill 的要求 |
| --- | --- |
| `prepare.py` 固定 17×12 网格，并非内容驱动；重跑会覆盖进度清单 | 自动计算，再用内容分析调整接缝；恢复时读已有状态，禁止重置成功记录 |
| 只要求宽高达标，把不同画幅统一压到 1280×1080 | 检查有效 crop 的两边尺寸和画幅，错误比例直接拒绝；不以拉伸补救 |
| 文件存在就可进入拼合，缺少逐块视觉门禁 | 必须经过登记与 `review`，只有 `qa_passed` 进入拼合 |
| ECC 配准失败被静默忽略，报告没有体现质量分数 | 默认只机械落位；任何附加几何修复都需要具体理由、记录和复核 |
| 按固定行列启用光流，曾使建筑窗格弯曲 | 建筑、文字等几何敏感对象优先保持形状，不能默认全图光流 |
| 减法式低频校色曾造成黑斑；阈值针对红金海报定制 | 不内置这张海报的颜色阈值；先修正生成一致性，额外校色须单独验证 |
| 字形保护使用固定框、金白色和局部例外 | 每张图重新分析文字和标志；不复用旧坐标，也不自动覆盖矩形区域 |
| 用 epsilon 处理零权重，报告布尔值直接写“完成” | 计算真实几何覆盖，缺口即失败；机械完成与视觉通过分开 |
| 局部拼合可能覆盖同名报告，交付目录混有过程检查图 | 每次运行独立保存；最终文件与过程预览清楚区分，导出不静默覆写 |

新实现中的透明度处理、画幅门禁、覆盖检查和恢复协议必须通过自己的自测；需要真实生图时仍按本 Skill 的规划、登记、审核、拼合和全接缝检查顺序执行。
